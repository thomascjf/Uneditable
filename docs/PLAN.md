## 1. 项目介绍

**一句话**：没碰过钱包的人，扫个码、按一下指纹，10 秒就能投出一票；这一票谁都改不掉，而且全场可以亲手验证。

**项目名（已定）**：**指纹上链**，英文标注 / GitHub 仓库名 `Uneditable`，域名前缀 `uneditable`。
一句话副标题（PPT 与提交简介用）：**按一下指纹，投一票，谁都改不掉。**

原有候选共 4 个：`Uneditable` / `指纹上链` / `One Vote, Two Truths` / `双栏真相`。选「指纹上链」的理由：现场是中文观众投票，四个字零理解门槛；直接对应唯一的技术亮点（passkey + 合约内 P256 验签）；且避开同场 640「无钱包扫码上链」的概念，不用「扫码」当叙事。`Uneditable` 保留作英文标注与仓库名，兼顾「改不掉」这个现场钩子。

**给谁**：非 Web3 背景的研发新人、大学生、现场观众。他们听过「去中心化」，但装钱包、领测试币、付 gas 三步就会劝退大半；也不理解「链上改不了」跟自己有什么关系。

**解决什么问题**：
1. 新人第一次参与链上活动的门槛（钱包 / 助记词 / 代币 / gas），把它压到「扫码 + 指纹」。
2. 「不可篡改」是抽象概念，用一屏对照把它变成可亲手操作的实验。

**产品形态**：
- 一个**大屏**（投影）：左右两栏。左栏「中心化数据库」，右栏「Monad 测试网」。同一批留言与投票，两份存储。
- 一个**手机页**（扫码进入）：从 40 支队伍中选一队投票、留一句话；默认「我自己出 gas」（连钱包签名），取消勾选则走「passkey + 转发器代付」。
- 一个**后台管理页**（二维码公开投屏）：一键修改 / 删除中心化库的留言和票数，用来现场演示篡改。

**核心现场动作**：先让观众投几票，然后把后台管理二维码投到屏幕上，请台下任意一位上来改票数、删留言——左栏立刻变，右栏纹丝不动；点开交易哈希在 MonadVision 上验证内容仍在。

**必须遵守的官方硬规则**（来自 PPT 第 5 页）：
- 代码当天从零编写，不接受已有个人项目（标准库 / 现成依赖可用）。
- 必须有**可公网访问的演示链接**，只在本地跑不计入评选。
- 公开 GitHub 仓库。
- 演示 3 分钟，幻灯片可有可无；路演顺序按提交顺序。

## 2. 两个亮点（只放大这两个）

### 亮点一：零门槛上链入口（技术内核，唯一必须讲透）

passkey 指纹签名 → 转发器代付 gas → **合约内用 Monad 的 P256 预编译（`0x0100`，EIP-7951）直接验证 passkey 签名**。

- 用户侧：0 安装 / 0 助记词 / 0 代币 / 0 gas。
- 链上侧：票确实由那枚 passkey 产生，合约自己验，不靠服务端口头保证。
- 放大方式：现场找 5 位从没碰过钱包的同学扫码投一票，大屏实时打出「X 秒上链」，点开交易展示验签数据。
- **可复用叙事**（导师原话的意思）：真正有价值的不是「一个投票应用」，而是一套活动基础设施——下一场黑客松、校园活动、会议投票，换一份 `teams.json` 就能直接拿来用，不用再教观众装钱包。这句用来收尾，把项目从「作品」抬到「能被别人接着用的东西」。

### 亮点二：让观众亲手篡改（现场钩子，用来换票）

名次由现场观众投票决定。不是我们后台偷偷改，而是把管理页二维码投在屏幕上，请台下的人上来改。左栏变、右栏不变，是三分钟里唯一的「哇」瞬间。

### 明确不讲（导师点名，避免被评委追问）

- 不讲「600ms 出块 / 低手续费」当卖点——任何便宜的快链都成立。
- 不讲「流式执行事件让大屏不用索引器」——链上事件本来就靠订阅 / 轮询，不是 Monad 特性。
- 不把「链上改不了」当主体结论——台下没人需要被说服。对照栏只当包装。

### 同场差异化（必须处理）

同场队伍 id 640「GENESIS GARAGE」简介是 *"A walletless live racing arena powered by Monad. Players scan, modify a car, challenge the champion, and watch every verified result evolve on the big screen."* ——「无钱包 + 扫码 + 大屏 + Monad」这个组合现场已经有人做。所以**不能用「扫码上链」当主叙事**，要压在两点上：① 可复用的零门槛上链基础设施（含合约内 P256 验签）；② 观众亲手篡改的对照实验。

### 撞车情况

创意导师回复：**无撞车项目**。相关项目：「monad-voting-dapp」（Monad Blitz @ 上海，未获名次）、「Hunch」（上海 V2.0，未进前 3）。今日导师额度剩余 19/20。

## 3. 技术实现具体方案

### 3.1 总体架构：单端口 Node 服务

```
手机浏览器(扫码) ─┐
大屏浏览器(投影) ─┼──> [ Node / Express 单端口 HTTPS 服务 ] ──> Monad Testnet RPC
后台管理页 ───────┘        │
                           ├── /public  静态前端（大屏 + 手机页 + 管理页）
                           ├── /api/*   业务接口 + 转发器 + 中心化库代理
                           ├── store.json（中心化数据，进程内 + 文件）
                           └── deployer.key（专用转发器钱包私钥，仅运行时）
                                  │
                                  └──> 合约 BlitzBoard (Monad Testnet)
```

**关键设计：手机端不直连 RPC**。所有链上读写走我们的服务代理。理由：现场手机 4G 访问境外 RPC 不稳定、公共 RPC 有 20 rps 限流、也便于统一缓存与轮询。前端只连我们的域名。

### 3.2 链上：合约 `BlitzBoard.sol`（Solidity ^0.8.24，用 solc 编译，不引 Hardhat/Foundry 以省时间）

数据：
- `struct Entry { uint8 kind; uint16 teamId; address author; bytes32 credHash; string text; uint64 timestamp; }`
- `Entry[] entries` + `mapping(uint16 => uint256) votes` + `mapping(bytes32 => bool) usedCredential` + `mapping(bytes32 => bool) usedChallenge` + `mapping(address => bool) hasVoted`
- 事件 `Voted(uint256 indexed id, uint16 indexed teamId, address indexed author, bytes32 credHash, string text, uint64 timestamp)`
- 事件 `Posted(...)`

写入入口（两条路写同一个合约、同一份数组，保证对照可比）：
1. `vote(uint16 teamId, string text, uint64 deadline, bytes sig)` —— 钱包直签路径。合约用 secp256k1 `ecrecover` 校验 EIP-712 签名（`teamId / text / deadline / chainId / address(this)`），恢复出的地址即 `author`。默认路径，用户自己出 gas。
2. `voteByPasskey(bytes authData, bytes clientDataJSON, uint256 r, uint256 s, uint256 qx, uint256 qy, uint16 teamId, string text, bytes32 credIdHash)` —— 转发器代付路径。合约：
   - 用 `0x02` SHA-256 预编译算 `clientDataHash = sha256(clientDataJSON)`；
   - `msgHash = sha256(authData || clientDataHash)`；
   - `staticcall` 到 `0x0100`，按 EIP-7951 传 160 字节 `msgHash || r || s || qx || qy`，要求返回 32 字节且值为 1；
   - 在 `clientDataJSON` 中校验 `type=webauthn.get`、`origin=https://<固定域名>`、`challenge` 等于预期模板（challenge 由服务端下发，绑定 `teamId / text / nonce / deadline / chainId / 合约地址`）；
   - 校验 `authData` 前 32 字节 = `sha256(rpId)`、`flags` 的 UP/UV 位；
   - `require(!usedCredential[credIdHash])`（每 passkey 限投一票）、`require(!usedChallenge[nonce])`（防重放）、`require(block.timestamp <= deadline)`。
   - `author` 记为转发器地址，但 `credHash` 记录该 passkey，链上可追溯「是这枚指纹投的」。

安全底线（导师要求做死）：防重放 + 每地址 / 每凭据限投；challenge 一次性；deadline 短时效。

### 3.3 两条用户路径

| | 默认：自己出 gas | 取消勾选：转发器代付 |
| --- | --- | --- |
| 前置 | 手机里有钱包、有 testnet MON | 什么都不用 |
| 流程 | 检测 `window.ethereum` → 连钱包 → EIP-712 签名 → 手机直接发交易 | WebAuthn `navigator.credentials.create/get()` → 把 assertion 交给服务端 → 服务端组交易并代付 |
| 链上入口 | `vote()` | `voteByPasskey()` |
| 兜底 | 无 provider 时提示「在钱包 App 内打开」并给「没有代币？」入口（水龙头码）；仍不行则引导取消勾选 | 服务端 nonce 队列 + 单飞，避免并发 nonce 冲突 |

页面顶部一个开关「我自己有 Monad 代币，自己付 gas」，**默认开启**（按用户要求）。

### 3.4 链下

- **中心化库**：`store.json`（留言数组 + 票数 map + 版本号），由 `/api/central/*` 读写。管理页提供「改票数 / 删留言 / 改文字」三个大按钮，每次改动写一条 `audit` 时间戳，大屏左栏立刻刷新。
- **大屏右栏**：服务端轮询 `eth_getLogs`（从上次区块起）读 `Voted/Posted`，或从合约 `entries` 增量读；每条展示内容、发起到确认耗时、可点开的交易哈希（链到 `https://testnet.monadvision.com/tx/<hash>`）。用 SSE 推给大屏，避免轮询风暴。
- **实时刷新**：SSE（`/api/stream`），左栏由服务端事件推、右栏由链上轮询结果推；同一份数据两个来源，视觉上严格左右对齐。
- **手机页**：40 支队伍用搜索框 + 按队名排序，不分页；提交后展示「已上链 / 交易哈希 / 用时」，并给「去大屏看看」的提示。

### 3.5 数据与配置

- `teams.json`（已存在，40 支，含 id / 队名 / 简介 / 人数）作为唯一投票选项源，前端构建时打进静态资源。
- 合约地址、chainId、RPC、explorer、rpId、origin 全部集中在 `config.json`，部署后只改一处。
- 合约 ABI 与地址写进 `README.md`，便于现场验证与评委查看。

### 3.8 分级交付（时间不够时按级砍）

- **L0 必达**：合约 `vote` 钱包路径 + 双栏大屏 + 中心化库 + 管理页篡改 + 手机扫码投票 + 公网可访问。这一层已经能完整演示，「让观众亲手篡改」的钩子成立。
- **L1 核心亮点**：passkey 注册/签名 + 转发器代付 + 合约内 P256 预编译验签 + 防重放/限投。**这是最想保住的一层**。
- **L1′ 降级**（若链上 WebAuthn JSON 解析卡住）：passkey 验签放在服务端（`@simplewebauthn/server`），合约只存 `credHash` 与签名摘要作为可查存证，界面与「0 门槛」体验完全不变；讲的时候诚实说「验签在服务端，链上留可验证凭证」，不冒充链上验签。亮点打折但不翻车。
- **L2 加分**：同步回执耗时显示、台下 5 人实测数据、录屏兜底、多语言。

**判定线**：16:30（剩余 2 小时，AGENTS.md 加速阈值）前若 L1 未跑通真机，立即切 L1′，不再死磕。

| E | GitHub 地址 | Mojo 提交表单必填 | 项目名已定为「指纹上链」，见第 1 节；GitHub 地址由工程任务产出 |

**私钥不是钱包地址**（最容易搞错的一点）：

- **地址**：`0x` + 40 位十六进制字符（20 字节），公开，用来收测试币、在浏览器查交易。**只有地址无法签名，部署合约和代付 gas 都做不了**。
- **私钥**：`0x` + 64 位十六进制字符（32 字节，共 66 个字符），秘密，用来对交易签名。文件里要的是这个。
- **助记词**：12 / 24 个英文单词，是派生所有账户的根，交出来等于交出整个钱包，**不要放进文件**。

MetaMask 导出路径：账户菜单 → 选中账户 → 「账户详情」→「显示私钥」→ 输入密码 → 复制。文件内容只放这一行 `0x...`，不放地址、不放助记词、不放 JSON。

自检（**不打印私钥内容**）：`node -e "const s=require('fs').readFileSync('.workbuddy/deploy-key.txt','utf8').trim(); console.log('format_ok:', /^0x[0-9a-fA-F]{64}$/.test(s))"`，再用 viem 的 `privateKeyToAccount(s).address` 派生出**地址**给用户确认（地址可以公开）。

这个钱包必须是新建的一次性测试网钱包、只放少量测试 MON、无任何真实资产，赛后作废；文件在 `.workbuddy/` 下已被忽略，不进 git。

### 4.2 技术卡点清单

| 卡点 | 严重度 | 处理 |
| --- | --- | --- |
| **A 私钥 / 测试币缺位** | 硬阻塞 | 最高优先级，先解锁。水龙头 429，建议直接用已有测试币 |
| **部署目录会连带上传凭证** | 高（安全） | 发布工具会压缩上传整个目录，只排除 `node_modules/.git/build`。必须另建**独立 `deploy/` 目录**，只放运行必需文件；`.mojo/`、`.workbuddy/`、`other-docs/`、`docs/` 一律不放进去。**唯一例外**：转发器运行时需要那把一次性私钥，单独放 `deploy/relayer.key`（内容同 `deploy-key.txt`），这是唯一允许随发布上传的密钥，且必须是无真实资产的一次性测试网钱包 |
| **HTTPS 与 RP ID 绑定** | 高 | WebAuthn 要求 secure context；passkey 的 rpId 与首次注册域名绑定，换域名后已注册凭据全部失效。因此**先定域名、部署成功后再开始 passkey 自测**，且全程不再改域名 |
| **部署沙箱出站 RPC 是否可达** | 中 | 部署后第一件事：从线上服务打一次 `eth_chainId`。不通则换 `rpc.testnet.monad.xyz` 等备用端点或改走代理 |
| **链上 WebAuthn JSON 解析** | 中高 | 最大实现风险。用固定 challenge 模板 + 常量 origin 降低合约字符串处理；失败即切 L1′ |
| **WalletConnect projectId** | 中 | 手机普通浏览器连钱包默认路径需要它。未申请则降级：检测注入 provider，无则提示「在钱包 App 内打开」或自动引导取消勾选走代付 |
| **公共 RPC 限流 / 现场网络** | 中 | 前端不直连 RPC，全走后端；后端缓存 + 单飞 + 1~2 秒轮询；准备录屏兜底 |

## 5. 公网部署方案

**主方案**：WorkBuddy 应用发布（单端口 HTTP 服务），把整理好的 `deploy/` 目录发布为在线 HTTPS 链接。

- 满足 PPT「必须有可访问演示链接」「本地跑不计入评选」。
- 服务必须监听 `PORT` 环境变量并绑定 `0.0.0.0`；用 `npm start` → `node server/index.js`，Express 同时托管 `public/` 静态文件，避免 Vite dev server 的 host 检查问题。
- 域名前缀固定为 `uneditable`（与项目英文名一致），一旦确定不再更换，避免 passkey rpId 失效。
- 沙箱**不提供数据库 / 缓存 / 消息队列**，我们的 JSON 文件存储不受影响；但不要引入 MySQL/Postgres/Redis。
- 需要用户明确说「发布 / 上线」才会执行（发布是覆盖线上链接的操作，需逐次确认）。

**备选**：Railway / Render / Vercel（官方文档也把 Vercel、Railway 列为便捷托管）。优点是生态熟，缺点是要额外注册、配置环境变量、可能耗时更久；作为主方案失败时的兜底。

**部署后验收清单**（按顺序，全过才算可演示）：
1. 线上打一次 `eth_chainId`，确认沙箱出站 RPC 通。
2. 合约地址已部署、MonadVision 上能查到、ABI 已同步到 `config.json`。
3. 大屏 / 手机页 / 管理页三个 URL 在**手机 4G**（非同一 WiFi）下都能打开，且是 HTTPS。
4. 手机真机完成一次 passkey 注册 + 一次投票，交易在浏览器里能查到。
5. 大屏右栏在 2 秒内出现新票；左栏管理页改票数后立刻变化、右栏不变。
6. 转发器钱包余额足够覆盖现场票数（预估每人 1 笔，留 3 倍余量）。
7. 三个二维码（投票 / 管理 / 水龙头）指向线上域名，不是 `localhost`。

### 8.3 Q&A 三问（提前背）

- 「这不就是个链上投票？」→ 重点不是投票，是**零门槛上链入口**：passkey + 合约内 P256 验签 + 代付 gas，换份名单就能复用到别的活动。
- 「代付 gas 不就又中心化了吗？」→ 转发器只负责付 gas、不能改内容；签名由用户设备产生、合约独立验签，内容不可被转发器伪造；而且用户随时可以切回自己付 gas。
- 「和同场另一个扫码上链项目有什么不同？」→ 我们是**可复用的参与基础设施 + 可亲手验证的不可篡改对照**，不是一次性的游戏。
